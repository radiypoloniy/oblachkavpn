# Облачка 0.9.1 — Windows-клиент

Актуальное состояние: 13 октября 2026 года. Внутренняя сборка на C#/WPF, .NET 10, Xray 26.9.9 и sing-box 1.14.3. Клиент написан с нуля; Throne используется как эталон сравнения.

## Запуск

В проекте после `./build.ps1` запустите `app-v09/Oblachka.exe`. В распакованном комплекте — `Oblachka.exe` из корня. Для этой сборки нужен .NET 10 Desktop Runtime x64. Самодостаточная сборка создаётся отдельно `./publish-standalone.ps1`; её каталог содержит runtime и не требует установки .NET.

1. Введите ключ подписки сервиса на первом экране.
2. Выберите сервер. Поиск, сортировка и избранное меняют только представление списка; подключение остаётся выбранным, даже если скрыто фильтром.
3. Выберите режим в «Настройки → Основное» и нажмите «Подключить».
4. Проверьте связь в «Диагностике». Успешный HTTPS-запрос подтверждает связь через ядро, а не отсутствие всех возможных утечек компьютера.
5. Для остановки нажмите «Остановить». В системном режиме дождитесь завершения восстановления сети.

Обычный режим создаёт локальный SOCKS/HTTP-прокси: его нужно указать в программе. Системный прокси Windows действует для программ, которые поддерживают эту настройку. Системный TUN направляет трафик компьютера через sing-box и запрашивает права администратора для отдельного сетевого помощника.

## Реализовано

- Активация ключом сервиса, подписки и сторонние профили раздельно, автоматическое обновление. Проверены 13 профилей реальной подписки, включая XHTTP extra.
- VLESS, Trojan и Hysteria2; срок, трафик и объявления панели; идентификатор устройства для лимита устройств.
- Трей, зашифрованное сохранение через Windows DPAPI, ограниченное восстановление и проверка серверов отдельным ядром.
- Поиск, сортировка по названию/стране/времени HTTPS-запроса, избранное. Неуспешные и устаревшие результаты идут после свежих успешных при сортировке по времени. Это не измерение скорости или ICMP ping.
- Избранное сохраняется вместе с подключениями, если включено запоминание. Идентичные имена одного источника имеют общую отметку; смена ключей панели её не сбрасывает.
- Системный TUN подключён к окну: helper с UAC, IPC, владение процессом, журнал восстановления, маршруты и DNS через sing-box.
- Код блокировки обходного трафика через брандмауэр Windows. При выключенном брандмауэре защита недоступна; окончательное подтверждение сценариев защиты ещё требуется.
- «Диагностика → Скопировать отчёт» или «Сохранить отчёт»: версия, ревизия, текущий режим и обезличенные коды. Ключи, профили, адреса и история сайтов не включаются.

## Что проверено и что осталось

TUN, TCP, DNS и UDP, возврат сети и ряд аварийных сценариев испытаны в отдельной Windows VM. Подробности и ограничения — [отчёт VM](docs/VM-TUN-RESULTS-2026-10-12.md) в папке docs. Результат одного стенда не подтверждает все сети и транспорты.

Главные оставшиеся задачи: окончательная проверка kill switch, IPv6 на реальной сети, длительные сессии, смена адаптера, конфликты с другими VPN. Правила сайтов и программ пока сохраняются как черновики и не применяются к рабочему сеансу. Полноценный установщик, Authenticode и автоматическая доставка обновлений ещё не готовы. Порядок работ — [NEXT-STEPS](docs/NEXT-STEPS.md).

## Сборки и упаковка

`./build.ps1` собирает обычный клиент в `app-v09`; `./test.ps1` — отдельный тестовый клиент в `app-v09-test`. Для повседневного запуска используйте обычный каталог. Версия и ревизия видны в настройках. «С изменениями» означает сборку из незакоммиченных исходников.

В `build-info.json` находятся полная ревизия, время сборки UTC, хеш исходников и DLL. `./package.ps1` отказывается упаковывать устаревшую сборку: после коммита или изменения исходников выполните `./build.ps1` снова. Пакет содержит обычную сборку, лицензии, инструкции и комплект VM; самодостаточный каталог пока упаковывается отдельно вручную.

`./verify-package.ps1 -ArchivePath <zip>` проверяет манифест, размеры, SHA256, закреплённые ядра, отсутствие тестового кода и подготовку VM без запуска TUN. Подпись манифеста пакета и Windows Authenticode — разные механизмы; тестовый ключ пакета не является подписью кода Windows.

Сохранённые подключения находятся в `%LOCALAPPDATA%/Oblachka/client-state.bin`. При запуске туннель выключен. Повреждённые данные не удаляются автоматически.

Прежние записи версий сохранены в [истории](docs/HISTORY-CLIENT-0.2-0.9.1.md); это исторические описания, которые могут содержать старые имена файлов и ограничения.
