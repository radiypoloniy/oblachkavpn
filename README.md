# Облачка 0.9 — Windows-клиент

## 0.9 — клиент сервиса, а не универсальный список

- Первый экран принимает **ключ подписки**, а не произвольную ссылку: короткий ключ, полную ссылку сервиса или ссылку без схемы. Подписка чужого хоста отклоняется с указанием раздела сторонних подписок, без сетевого запроса.
- `ServiceBrand` — единственное место, где описан сервис: имя, версия, `User-Agent`, хост подписки, путь, адрес поддержки.
- **Узлы сервиса и сторонние живут рядом.** Сторонняя подписка больше не затирает список сервиса; сторонние узлы помечены в списке. Подбор маршрута, автовосстановление и измерения работают только по узлам сервиса: переключить пользователя на чужую конфигурацию клиент не вправе. «Настройки → Подписка → Другие подписки».
- Прогон реальной подписки: 13 узлов из 13, закреплённые Xray 26.9.9 и sing-box 1.14.3 приняли все конфигурации. Менять панель не требуется — Base64-ссылки несут XHTTP `extra` целиком. Подробности: [REMNAWAVE.md](docs/REMNAWAVE.md).
- Клиент обращается к пользователю **на «вы»**; `check-voice.ps1` следит за возвратом к «ты».
- Перевод на **.NET 10**: у .NET 8 поддержка заканчивается 10.11.2026.
- Тестовый код вынесен в отдельный проект `tests/Oblachka.Tests.csproj`. В поставляемом `RoutePilot.exe` его нет, это проверяет `check-no-test-code.ps1`.
- Резервная копия репозитория: `backup.ps1` держит зеркало на втором диске.
- Сборка и проверки используют `app-v09`. План и оценка объёма работ: [PRODUCT-PLAN-2026-10-12.md](docs/PRODUCT-PLAN-2026-10-12.md).

Чего в 0.9 по-прежнему нет: TUN, kill switch, управления DNS и IPv6, установщика и подписи кода. Это остаётся режимом локального прокси, а не общесистемным VPN.

## Возможности 0.8

- Автообновление подписки после запуска и раз в 6 часов, с задержками при отказе. После HTTP 401/403 фоновые повторы остановлены до ручного обновления. Срок и остаток трафика показываются только из заголовка сервера.
- Выбор сохраняется при перестановке узлов и смене ключей, если имя узла уникально. Названия и флаги в строках не заменяются измерениями.
- Проверка всех серверов отдельным временным ядром, до 5 минут; выбор лучшего по успешному HTTPS-запросу за последние 20 минут. Скорость и ICMP ping этим не измеряются.
- Настройка автоперезапуска также включает проверку двух независимых сайтов через SOCKS каждые 45 секунд. После трёх раундов без ответа запускается ограниченный подбор. HTTP-ошибка сайта не считается отказом транспорта. После пробуждения/возвращения сети проверка ускоряется. Это запросы к Microsoft/Cloudflare через выбранный сервер, без прямого запасного маршрута.
- Черновики правил сайтов и программ сохраняются шифрованно; можно проверить конфигурацию закреплёнными ядрами. В текущем SOCKS-сеансе они не применяются. Правила программ предназначены для будущего sing-box TUN перед любым ядром.
- Обезличенная диагностика содержит только коды событий и агрегаты; нет свободного текста, адресов, профилей или токенов.
- Подписываемые пакеты, локальный установщик, обновление отдельной папкой и откат без удаления прежней сборки: [DELIVERY-0.8.md](docs/DELIVERY-0.8.md). Полноценный Setup.exe, Windows Authenticode и автоматическая доставка обновлений пока не подключены.
- Подготовка VM с нуля и BIOS: [START-HERE.md](vm-kit/START-HERE.md).

Системный TUN, защита при обрыве, DNS/IPv6 компьютера и реальные Windows-изменения по-прежнему требуют испытания в отдельной VM. Рабочую сеть основного ПК эта сборка не меняет.

Собственный интерфейс на C# / WPF и готовые ядра Xray 26.9.9 / sing-box 1.14.3. Это начало клиента, написанного с нуля, без форка Throne. Название интерфейса — Облачка; имя файла RoutePilot.exe пока сохранено.

## Запуск

Открой `app-v082/RoutePilot.exe` (после `.\build.ps1`) в рабочей папке; в распакованном архиве `RoutePilot.exe` находится в корне. Предыдущие сборки сохранены в `app`, `app-v03`, `app-v04` и `app-v05`. Нужен **.NET 8 Desktop Runtime x64**; на этом компьютере он уже установлен. Администратор не требуется. Приложение пока не подписано и не имеет установщика.

1. Добавь VLESS-ссылку, клиентский JSON Xray / sing-box или HTTPS-подписку кнопкой в приложении.
2. Если в подписке несколько подключений, выбери нужное.
3. Нажми «Подключить»: приложение проверит конфигурацию и запустит локальный SOCKS5.
4. Нажми «Проверить»: выбранный HTTPS-запрос должен пройти через SOCKS и VLESS-сервер. «Прокси запущен» означает готовность локального ядра; «Туннель проверен» означает успешный запрос.
5. Программа, которой нужен туннель, должна использовать показанный SOCKS5 на `127.0.0.1`. При первом подключении порт выбирается автоматически; до закрытия приложения он сохраняется при переподключении и подборе узла. Занятый порт вызывает явную ошибку. Перезапуск приложения позволяет выбрать новый порт.

## Ядра и стенд

**Второе ядро.** Нативный sing-box JSON для VLESS и Hysteria2 выбирает sing-box автоматически. VLESS URI и Xray JSON используют Xray; XHTTP остаётся на Xray. Автоматического перевода JSON между ядрами нет. Для sing-box поддержан ограниченный набор настроек: внешние файлы, цепочки, неизвестные поля и отключённая проверка TLS отклоняются. Профили разных ядер можно смешивать в подписке и ручном подборе. В локальных тестах проверены VLESS/TLS между sing-box и Xray и Hysteria2/QUIC/TLS; другие варианты требуют стенда.

**Повторяемые замеры.** `--lab <plan.json> <report.json>` запускает ограниченный последовательный стенд и создаёт новые JSON/CSV без адресов и секретов. Инструкция — `docs/LAB.md`. Он измеряет запуск ядра и получение заголовков HTTP через SOCKS, не пропускную способность и не ICMP ping.

**Размер исходников.** Окно разделено на состояние/подключение, импорт, диагностику и тестовые сценарии; тесты — на группы. Сборка проверяет предел 250 строк / 24 КиБ на исходник. Адаптер ядра содержит только различия команд и конфигурации; жизненный цикл процесса общий.

## Подписки и восстановление

**Резервные адреса подписки.** В окне «Добавить подписку» укажи до пяти полных HTTPS-ссылок, по одной на строку. Каждая ссылка задаётся явно: токен из первого адреса не копируется на произвольный домен. Загрузка идёт последовательно; последний успешный адрес проверяется первым при обновлении. Общий лимит — 60 секунд. Redirect не следуется. Ответ 401/403 останавливает загрузку; причину такого ответа клиент не определяет автоматически.

**Обновление подписки.** Кнопка обновления использует адреса из памяти. Отказ сохраняет старый список. При активном туннеле новый список откладывается до остановки: действующий процесс и его профиль не меняются. Выбранное подключение сохраняется, если оно осталось в новой подписке; изменение порядка JSON-полей или имени не сбрасывает выбор. При включённом запоминании адреса восстанавливаются после выхода. Автоматическое обновление по расписанию ещё не включено.

**Подбор работающего подключения.** Кнопка сначала останавливает текущий туннель, затем проверяет выбранный профиль и следующие подключения в порядке подписки. Максимум — шесть попыток и две минуты. Успех означает выполненный запрос через SOCKS; найденный туннель остаётся запущенным. При отказе всех попыток или отмене ядро выключается. HTTP-ошибка сайта проверки останавливает подбор, вместо объявления всех узлов неработающими. «Остановить» отменяет процесс. Во время переключения прежние TCP-соединения прерываются.

Это ручной подбор по одной команде, без постоянных фоновых запросов. Цепочки L1/L0, мониторинг нескольких сайтов и автоматическая смена узла в фоне пока не реализованы. Подбираются только профили, которые умеет импортировать текущая сборка.

**Это пока локальный TCP-прокси, а не системный VPN.** Маршруты, DNS, настройки прокси Windows и firewall не меняются. Остальные программы продолжают использовать своё соединение. Общесистемный kill switch и защита от утечек DNS здесь ещё не реализованы. Для доменных запросов через SOCKS приложение-потребитель должно передавать имя серверу, а не предварительно разрешать его локально.

Сворачивание оставляет окно в панели задач. Закрытие окна по умолчанию останавливает собственное ядро; настройка позволяет оставаться в трее. «Завершить» в трее всегда останавливает ядро. Дочерние процессы обоих ядер помещаются в Windows Job Object. Вторая копия из той же папки не запускается.

## Что реализовано

- Импорт VLESS URI, текстовой и Base64-подписки, JSON outbound или массива клиентских конфигураций Xray.
- TLS и REALITY; транспорты TCP/RAW, XHTTP, WS, gRPC и HTTPUpgrade. Полный тест передачи трафика выполнен для TCP/TLS и XHTTP/TLS. Остальные варианты требуют отдельной проверки на стенде.
- Сохранение XHTTP extra при импорте. Непонятные параметры URI приводят к явному отказу, вместо тихой потери настроек.
- Выбор подключения, запуск, остановка, повторное подключение, управление из трея.
- Необязательный автоперезапуск при **завершении процесса ядра**: до трёх попыток за две минуты. Это пока не детектор недоступности сервера.
- Проверка запроса через явный SOCKS без прямого обхода при отказе. Показанное время — время HTTP-запроса, не ICMP ping.
- Обезличенный отчёт по отдельной команде пользователя.

## Данные и ограничения

Профили и URL подписки сохраняются через Windows DPAPI при включённом запоминании. Конфигурация передаётся обоим ядрам через stdin, без временного файла с UUID и адресами. При следующем запуске сохранённый профиль восстанавливается без запуска ядра. Приложение не читает конфигурацию Throne, браузерные данные или буфер обмена автоматически. Кнопка копирования пишет в буфер только локальный SOCKS-адрес. План стенда — отдельный явно указанный пользователем файл с секретами; автоматически приложение его не создаёт.

В отчёт не включаются профили, UUID, адреса серверов, URL подписок и сырой журнал Xray. Импортированные ссылки на внешние сертификаты/ключи и запись TLS master key log отклоняются. Проверка TLS не отключается.

Загрузка подписки выполняется прямым HTTPS-запросом только по нажатию. Перенаправления не следуются; нужна конечная ссылка. Ограничения: 1 МБ, до 200 подключений. Совместимость с реальной выдачей вашей Remnawave ещё нужно проверить. Полные правила маршрутизации/DNS из импортированного JSON не применяются: извлекаются только поддерживаемые outbounds. Цепочки дополнительных outbounds пока не поддерживаются. Формат vnext соответствует закреплённому Xray 26.9.9; более новые схемы не угадываются.

Текущий этап не доказывает равенство стабильности с Throne в реальной сети. Для этого предусмотрена отдельная матрица в `docs/NEXT-STEPS.md`.

## Разработка

Установленный .NET SDK 8 достаточен; сторонних NuGet-зависимостей нет. Из PowerShell в этой папке:

```powershell
.\build.ps1
.\test.ps1
.\package.ps1
```

Скрипты не удаляют файлы. Сборка и тесты используют `app-v082`. Xray и его лицензия копируются из известного `app/tools`, остальные данные этой папки не читаются. sing-box берётся из `vendor/sing-box-1.14.3` после проверки SHA256 архива и распакованных бинарников. Каждый отчёт тестов и архив получает новое имя. Тесты используют только loopback; конфигурации и сертификаты стенда не сохраняются на диск и в хранилище сертификатов Windows. Тест завершения процесса убивает только запущенный им контроллер и его дочернее ядро.

Исходники — `src`; отдельные экраны — `src/Views`. `--preview <file.png> <page> [compact]` формирует снимок с синтетическими подключениями без сетевых запросов; страницы welcome, profiles, servers, routes, diagnostics, settings, tray. `--self-test <report.json>` запускает проверки реального локального ядра. `--ui-self-test <report.json>` проверяет импорт, навигацию, поиск, настройки, трей и циклы запуска/остановки через настоящий WPF dispatcher без запросов к внешнему серверу. Проверка открытия из трея кратко показывает собственное тестовое окно; сохранение проверяется только в изолированной папке теста.

В комплект локального тестового архива входят только приложение, ядра, лицензии и документация. Тестовые каталоги, планы замеров, отчёты, отладочные символы и geo-базы в архив не включаются. Происхождение бинарников и необходимые действия перед публичным распространением — `THIRD-PARTY.md`.
