# Аудит клиента и исправления 0.8.2 · 12 октября 2026

## Итог аудита 0.8.1

Код прототипа аккуратный: конфигурация ядрам через stdin, без сырых логов, DPAPI, атомарная запись, Job Object, отказ от отключённой проверки TLS. Но как продукт клиент не готов: это локальный SOCKS5, а не VPN; совместимость с реальной подпиской Remnawave не проверена; поддержка .NET 8 заканчивается 10.11.2026.

## Что сделано в 0.8.2

### Импорт
- `ShareLinks.cs`: разбор `vless://`, `trojan://`, `hy2://`, `hysteria2://`. Ссылка Trojan по умолчанию TLS; без TLS/REALITY отклоняется.
- Незнакомый параметр по-прежнему не теряется молча, но в сообщении указано его имя: так первая реальная подписка сразу покажет, что добавить.
- `Profiles.XrayEndpoint` — общий доступ к адресу сервера для VLESS (`vnext`) и Trojan (`servers`); его используют TUN-закрепление и VM-проверка.
- Проверено реальными Xray 26.9.9 и sing-box 1.14.3 (`-test` / `check`): Trojan WS/TLS, Hysteria2 с salamander и диапазоном портов, `mldsa65Verify`, `echConfigList`.

### Системный прокси
- Локальный порт ядра принимает SOCKS5 и HTTP: Xray 26.9.9 socks-inbound уже понимает HTTP (проверено), у sing-box inbound заменён на `mixed`.
- `SystemProxy.cs`: HKCU `Internet Settings` (без прав администратора). Перед изменением исходные `ProxyEnable/ProxyServer/ProxyOverride/AutoConfigURL` пишутся в `%LOCALAPPDATA%\Oblachka\system-proxy-backup.json`.
- Возврат: при остановке, выходе, завершении сеанса Windows и при следующем запуске после аварии. Если прокси уже заменила другая программа (Throne и т.п.), её настройки не трогаются.
- При падении ядра прокси остаётся: браузер останавливается, а не уходит напрямую, пока не сработает восстановление или «Остановить».
- Не покрывает: UDP, игры, программы без поддержки системного прокси. Это задача TUN.

### Прочее
- Версия 0.8.2, сборка в `app-v082`; `app-v081` не трогается.
- Новые проверки: 11 импорта ссылок, 7 системного прокси (включая HTTP CONNECT на порт обоих ядер).

## Чем проверено и чем нет

- Компиляция всего C# (включая WPF code-behind) — без ошибок.
- Новые и затронутые проверки импорта, подписок и sing-box прогнаны на Linux с реальными ядрами — пройдены. Не запускались на Linux только проверки, требующие Windows (Job Object, DPAPI, named pipes, WPF).
- **Не проверено:** компиляция XAML-разметки (только проверка корректности XML), полный `test.ps1` на Windows, реальная запись в реестр, `publish-standalone.ps1` (на этой машине нет SDK 10 и доступа к nuget.org из среды проверки).

## Как проверить у себя

```powershell
cd "$env:USERPROFILE\Desktop\VPN-приколы\windows-client"
.\build.ps1
.\test.ps1
```

Затем вручную: «Настройки → Основное → Системный прокси Windows», подключиться, открыть сайт в браузере, остановить и проверить «Параметры → Сеть и Интернет → Прокси». Перед этим отключи системный прокси/TUN Throne, чтобы не путать результаты.

## Что осталось (по приоритету)

1. **Прогон на реальной подписке Remnawave** тестового пользователя: сколько профилей импортировано, какие причины отказа.
2. **.NET 10**: `winget install Microsoft.DotNet.SDK.10`, затем `.\publish-standalone.ps1`; после проверки поменять `TargetFramework` в csproj.
3. **Бэкап**: приватный remote для git (сейчас единственная копия на рабочем столе).
4. **Секреты в корне `VPN-приколы`**: `пароли.txt` (116 строк открытым текстом), 8 JSON-профилей с REALITY privateKey, `server-*.md` с паролями. После сверки с хранилищем Аптечки — удалить или убрать из папки, к которой ходят ИИ-агенты.
5. **HWID** (`x-hwid` и связанные заголовки) — до включения лимита устройств в панели.
6. **TUN на sing-box + kill switch** — по vm-kit, только в VM.
7. Тестовый код (`SelfTests.*`, `*Fixtures`, `--lab`) — в отдельный тестовый проект; сейчас он внутри RoutePilot.exe.
8. Тексты интерфейса для клиента, а не разработчика: «Прокси запущен», «SOCKS5», версии ядер на главном экране; пустые плитки «Время» / «Получено».
9. Подпись кода (Authenticode) и установщик — продумать заранее: купить сертификат из РФ проблематично.
10. Пароль на SOCKS для внутренних временных ядер измерений. Основной порт остаётся без пароля: системный прокси Windows не умеет авторизацию.
