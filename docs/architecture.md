# Как устроена Облачка

Клиент — окно WPF без прав администратора. Трафиком занимаются готовые ядра Xray и sing-box. Системные изменения (TUN, маршруты, фильтры WFP) делает отдельная сетевая служба. Окно её только просит.

```text
 ┌──────────────────────────── Oblachka.exe (пользователь) ────────────────────────────┐
 │  Окно WPF: главный экран, «Все серверы», настройки, трей                              │
 │    │                                                                                  │
 │    ├─ Подписки и профили ── разбор ссылок, JSON, Base64, Clash; группы подписок       │
 │    ├─ Маршрутизация ─────── правила сайтов и программ, geosite/geoip → правила ядра   │
 │    └─ Engine ─────────────── запускает ядро, следит за ним, переподключает            │
 │          │                                                                            │
 │          └─► xray.exe / sing-box.exe  (127.0.0.1: SOCKS/HTTP → сервер)                │
 └──────────────────────────────────────┬────────────────────────────────────────────────┘
                                        │ именованный канал (JSON, аренда сессии)
 ┌──────────────────────────── служба OblachkaNetwork (SYSTEM) ─────────────────────────┐
 │  Сетевая сессия: журнал изменений, TUN через sing-box, защита WFP, откат при сбое     │
 └───────────────────────────────────────────────────────────────────────────────────────┘
```

## Режимы подключения

| режим | что делает | права |
|---|---|---|
| Браузеры (прокси) | ядро слушает локальный SOCKS/HTTP; системный прокси Windows указывает на него | не нужны |
| Весь компьютер (TUN) | служба поднимает TUN sing-box. Ядро окна получает трафик через свой вход с паролем на loopback. WFP закрывает утечки мимо туннеля | служба (ставится установщиком) |

Без установленной службы окно запускает помощника с запросом UAC. Внутри та же сетевая сессия.

| `src/Profiles` | ссылки VLESS/Trojan/Hysteria2, подписки (Base64, JSON, Clash/Mihomo, sing-box), зеркала, группы, сохранение (DPAPI), перенос из других клиентов |
| `src/Core` | `Engine` и адаптеры ядер, проверка конфигурации, отклик серверов, автовыбор, диагноз отказа, лестница подбора, обход DPI (разрезанное рукопожатие) |
| `src/Routing` | профили маршрутизации (в т. ч. заголовок Happ), разбор geosite/geoip, сборка правил, каталог программ |
| `src/Network` | канал к службе, служба, сетевая сессия и журнал, TUN, WFP, системный прокси |
| `src/NetworkDoctor` | проверка и починка сети Windows: прокси, DNS, маршруты, остатки обходов блокировок |
| `src/Zapret` | обход блокировок без VPN: манифест набора Flowseal, белый список аргументов winws, установка и запуск в службе, подбор стратегии ([zapret.md](zapret.md)) |
| `src/Qr` | распознавание QR-кодов с экрана и из буфера (своя реализация, без библиотек) |
| `tests` | самопроверки и стенды; отдельный `Oblachka.Tests.exe` |
| `installer` | сценарий Inno Setup |

## Главные решения

**Ядро — отдельный процесс.** Конфигурация передаётся через stdin и на диск не пишется. Процесс привязан к Job Object окна и умирает вместе с ним. Перед запуском конфигурация проверяется самим ядром (`xray run -test`, `sing-box check`).

**Профиль — один outbound.** Из подписки берутся только параметры подключения. Локальный вход и маршруты клиент строит сам, поэтому чужая конфигурация не может тихо пустить трафик напрямую.

**Служба подчиняется только своей копии.** Канал принимает клиентов из папки службы в Program Files, окно сверяет PID службы с диспетчером служб. Подробно — [network-service.md](network-service.md).

**Проверка связи — тем же путём, что у программ.** В режиме «Весь компьютер» окно проверяет не только SOCKS ядра, но и обычный запрос через маршруты Windows. Если трафик компьютера не проходит, окно пересобирает туннель, а затем честно показывает «Интернет закрыт» с кнопкой выключения. Подробно — [network-service.md](network-service.md#проверка-связи).

**zapret под защитой от утечек.** WinDivert отправляет пакеты заново, и Windows видит их как соединения от System — защита их режет. Пока работает winws, служба разрешает System только порты его стратегии — [zapret.md](zapret.md#режим-весь-компьютер).

**Пинг — это задержка через сервер, а не до входа.** Отклик входа (TCP-рукопожатие) у каскадов — единицы миллисекунд при настоящих сотнях, поэтому числом он не показывается и в автовыборе не участвует. Замер идёт отдельными ядрами параллельно; под «Весь компьютер» — по адресам, которые защита разрешила ядрам.

**Пул автовыбора.** Серверы обхода белых списков — дорогие каскады для своей задачи — по умолчанию вне пула. Пул ограничивает выбор лучшего, переключение при обрыве и фоновый замер.

**Сеть всегда возвращается.** Каждое системное изменение сначала пишется в журнал. При падении окна, ядра или службы, при перезагрузке журнал позволяет откатить ровно свои изменения.

**Подписки — группы.** Каждая подписка — своя группа: обновление заменяет только её. Одиночные ссылки копятся в группе «Вручную». В списке серверов у каждой группы своя вкладка.

**Данные пользователя не уходят.** Подписки и настройки шифруются DPAPI в `%LOCALAPPDATA%\Oblachka`. Отчёт диагностики обезличен: в нём нет ключей, адресов и истории сайтов.

## Ограничения кода

- Не больше 250 строк и 24 КиБ на файл (`scripts/check-source-size.ps1`). Если файл растёт, ответственность выносится в отдельный класс.
- Интерфейс обращается к пользователю на «вы» (`scripts/check-voice.ps1`).
- Тестовый код не попадает в `Oblachka.dll` (`scripts/check-no-test-code.ps1`).
