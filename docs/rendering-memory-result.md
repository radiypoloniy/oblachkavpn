# Измеренная экономия полного WPF-окна

Дата: 2 ноября 2026 года. Экономный рендеринг включён для обычного интерфейса.
Входы службы/helper не вызывают настройку рендеринга. Для возврата прежнего режима
полностью завершить клиент через трей и запустить с `--hardware-rendering`.

## Стенд и результаты

Три последовательные пары отдельных процессов, одна машина, одинаковое полное WPF-окно,
два синтетических профиля, аналитика и 40 переходов между главным экраном и серверами,
затем скрытие. Последующие закрытие и диагностический GC в стенде не входят в сравнение.
Установленный клиент, реальные подключения и настройки пользователя не менялись.

Медианы; МиБ = 1024² байт:

| Метрика | Прежний режим | Экономный режим | Изменение |
| --- | ---: | ---: | ---: |
| Private Bytes скрытого полного окна | 100,50 | 78,76 | −21,74 МиБ / −21,6% |
| Private Working Set того же процесса | 60,23 | 55,29 | −4,94 МиБ / −8,2% |
| CPU-время 40 переходов, мс | 1640,63 | 1750,00 | +6,7% |
| Длительность серии переходов, мс | 1139,72 | 1177,67 | +3,3% |

До нагрузки переходами первая пара давала 79,89 → 60,27 МиБ Private Bytes и
43,38 → 38,77 МиБ Private Working Set; это один запуск, не медиана серии.
Исходные отчёты: `out/render-memory/{default,software}-{1,2,3}.json`.
В рабочем клиенте нет принудительного GC или обрезания working set.

Часть затрат графического пути сменяется программной отрисовкой: память ниже, CPU при
перерисовке может быть выше. Небольшой тест навигации не доказывает отсутствие замедления
на всех устройствах, мониторах, DPI и анимациях. Сохранён возврат прежнего режима.
Нельзя подменять Private Bytes частным рабочим набором. Нельзя обещать конкретное
«85 → N МБ» на компьютере пользователя по этим синтетическим профилям.

## Сопутствующее изменение

ClientTraffic владеет потоком скорости, программными счётчиками, общей выборкой соединений,
суточными/часовыми итогами, журналом, историей скорости и обнаружением зависания трафика.
Окно читает данные; его закрытие не обрывает счётчик и не освобождает общий семплер.
Таймер и отмена чтения принадлежат runtime и завершаются вместе с ним.
Проверены смена дня, дельты программ, работа после сборки WPF-окна GC и отсутствие WPF
в процессе изолированных фоновых проверок.

build.ps1: без предупреждений. test.ps1: 429 логических, 72 оконные и 16 фоновых
проверок успешно. Поставляемая DLL не содержит проверяемых тестовых символов.

## Что не завершено

Полная выгрузка процесса интерфейса ещё не включена. В фонового владельца предстоит
перенести zapret и оставшиеся уведомления/команды, затем подключить полный MainWindow
к IPC. Нельзя включать завершение WPF-процесса раньше и терять эти функции.
Это остаётся незавершённой частью первоначального плана, а не полученной экономией.
Далее измерять общую RAM всех процессов, время открытия окна, повторные открытия,
память больших подписок, фоновые пробуждения и CPU на реальном трафике. Настройки
сетевого ядра менять по отдельным замерам пропускной способности и задержки.
