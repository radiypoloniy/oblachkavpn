# Сетевая служба — 14 октября 2026

Служба `OblachkaNetwork` заменяет помощника с UAC там, где приложение установлено. Внутри та же сетевая сессия, журнал, туннель и защита WFP. Без установленной службы окно по-прежнему запускает помощника с запросом прав — переносная сборка и комплект проверки работают как раньше.

## Что меняется для пользователя

- Нет запроса прав администратора при каждом подключении.
- **Аварийное завершение окна больше не снимает защиту.** Помощник жил вместе с окном и при его гибели возвращал обычную сеть. Служба оставляет сессию: туннель без ядра окна ничего не несёт, фильтры держат сеть закрытой. Снимают её «Восстановить сеть» (теперь без UAC), новое подключение, остановка службы или перезагрузка.
- Штатный выход из приложения, как и раньше, останавливает подключение и возвращает сеть.

Новое подключение поверх оставленной сессии сначала снимает её: иначе адреса узлов не разрешить. Между снятием старой защиты и постановкой новой есть окно в несколько секунд (разрешение адресов узлов) — как при обычном первом подключении.

## Граница доверия

Служба работает от SYSTEM, поэтому:

- **Ставится только из Program Files.** `Oblachka.exe --install-service` отказывает (код 3), если сборка лежит в папке, куда пишет пользователь: иначе любая его программа подменила бы `Oblachka.exe` и получила SYSTEM.
- **Подчиняется только своей копии.** По PID клиента канала служба берёт путь его исполняемого файла; допустимы `Oblachka.exe` и `Oblachka.Tests.exe` из папки самой службы. Писать туда может только администратор. Посторонний клиент получает разрыв канала, причина пишется в `helper-failure.txt`.
- **Окно проверяет службу.** PID сервера канала должен совпасть с PID службы по данным диспетчера служб: программа, занявшая имя канала раньше службы, не пройдёт. Копия приложения не из папки службы получает понятный отказ, а не разрыв.
- **Канал только для локальных пользователей.** ACL канала: SYSTEM — полный доступ, INTERACTIVE — чтение и запись, NETWORK — запрет.
- **Журнал в ProgramData с собственными правами.** SYSTEM и администраторы — полный доступ, пользователи — чтение (окно по журналу видит оставленную сессию). Папку, созданную до службы кем-то без прав администратора, служба удаляет и создаёт заново: иначе можно было бы подложить журнал.

Что не закрыто: программа того же пользователя может управлять запущенным окном (отладка, внедрение) — как у любого клиентского VPN. Подпись Authenticode и проверка подписи клиента — вместе с установщиком.

## Команды

| команда | что делает | коды |
|---|---|---|
| `Oblachka.exe --install-service` | регистрирует службу для этой копии, автозапуск, перезапуск при сбое, запускает | 0, 2 нет прав, 3 не Program Files, 4 отказ SCM |
| `Oblachka.exe --uninstall-service` | останавливает (сеть возвращается), удаляет | 0, 2, 4 |
| `Oblachka.exe --network-service` | точка входа для диспетчера служб | — |

Протокол канала тот же (`HELPER-IPC.md`), добавлена команда `Recover` без параметров: снять сессию, оставленную прежним владельцем. Свою живую сессию через неё не снять — только `Release`.

## Проверено на стенде

Сборка скопирована в `C:\Program Files\Oblachka`, служба зарегистрирована оттуда.

| сценарий | результат |
|---|---|
| регистрация из `C:\lab\app` | отказ, код 3 |
| регистрация из Program Files | служба Running, Auto, LocalSystem |
| права `ProgramData\Oblachka` | SYSTEM, администраторы — полный; пользователи — чтение |
| посторонний клиент (PowerShell) пишет `Recover` в канал | разрыв, «К службе подключилась посторонняя программа» |
| полный прогон `--system-tunnel-check` через службу | перенаправление, защита, смерть ядра, откат, правила — как у помощника |
| окно (отдельный процесс-владелец) убито | журнал Applied, фильтров 14, интернета нет |
| затем «Восстановить сеть» | Released, фильтров 0, выход обычный |
| удаление службы при оставленной сессии | служба удалена, фильтров 0, интернет есть |

Не проверено: нажатия в самом окне со службой (путь тот же — `NetworkHelperConnection`, `SystemTunnelSession`), перезагрузка с оставленной сессией, выход из учётной записи и второй пользователь.
