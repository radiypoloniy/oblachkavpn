# Клиентские блоки 0.8

## Проверка и восстановление

`TunnelHealth` — политика над результатами запросов. Успех любого сайта или HTTP-ответ с ошибкой сбрасывает счётчик недоступности: транспорт дошёл до сайта. Повторный запрос ко второму независимому домену нужен при сетевом отказе первого. Три полностью неудачных раунда допускают восстановление. Отмена раунда не меняет счётчик.

Фоновая проверка включается настройкой «Восстанавливать автоматически», по умолчанию выключена. Период 45 секунд; после старта/пробуждения/возвращения доступности сети — через 3 секунды. Цели Microsoft и Cloudflare получают обычные HTTPS-запросы только через текущий SOCKS. Это не доказательство доступности всех сайтов или отсутствия утечек компьютера. Работа в фоне отключена во всех UI-фикстурах, включая изолированное тестовое хранилище.

Окно сохраняет единственного владельца операции: проверка, запуск, импорт, измерение и подбор не выполняются параллельно. Автовосстановление использует тот же подбор до 6 узлов/2 минут, что ручное действие. Повторы ограничены тремя попытками за 2 минуты с задержками и jitter. Ручная остановка отменяет операции. После исчерпания лимита требуется ручное подключение. Проверка не использует DIRECT как запасной маршрут.

## Подписки и измерения

Обновление — после запуска и каждые 6 часов, если настройка включена. Ошибки дают интервалы 5/10/20/40/60 минут. HTTP 401/403 прекращает фоновые повторы до ручной проверки; отказ доступа не называется автоматически истёкшим сроком. Работающий туннель не заменяется: список ждёт остановки. Отмена загрузки также откладывает следующий фоновый запрос.

`subscription-userinfo` разбирается отдельно от профилей: ограничение 2 КиБ, неотрицательные значения, безопасный расчёт остатка без переполнения. Некорректный заголовок не ломает импорт; отсутствующие данные не выдумываются. Сведения показывают последнее полученное состояние сервера, а не текущую статистику процесса. После обновления выбор сохраняется по отпечатку, затем по уникальному исходному имени и ядру при смене ключей; неоднозначные имена не угадываются.

Измерения владеют отдельным временным контроллером, доступны при остановленном основном подключении, ограничены 5 минутами. Отмена останавливает текущий временный процесс и не запускает следующий. «Лучший» выбирается только среди успешных результатов не старше 20 минут; результаты из будущего исключаются. Это время HTTPS-запроса, не ICMP ping, скорость или геолокация выхода. Имена строк остаются из подписки, без дополнительных меток.

## Диагностика и настройки

Отчёт формируется закрытой схемой: версия, режим, состояние, счётчики, время/код события и результат попытки. Свободный текст, исключения, имя узла, адрес, UUID, токен, URL проверки и отпечатки профилей туда не попадают. Никакая отправка отчёта в сеть не выполняется.

Настройки, сведения подписки, измерения и черновики правил находятся внутри прежнего DPAPI-хранилища v1. Новые поля необязательные: старые состояния загружаются с безопасными значениями по умолчанию. Личные хранилища для проверок не читались.

## Правила

Сайты: нормализация IDN, запрет URL/путей/портов/IP/дубликатов, до 100 правил. Более точные поддомены идут раньше родительских. Компиляторы Xray и sing-box сохраняют прежний default tunnel; DIRECT появляется только как явно добавленное пользователем действие. Конфигурация проверяется ядром в памяти, без запуска подключения.

Программы: имя `.exe`, до 100 правил, запрет путей и повторов без учёта регистра. Компилируются в TUN-слой sing-box перед любым ядром. Hijack DNS и запрет прочего UDP имеют приоритет над программами. Возможность сопоставления процесса на Windows описана в [документации sing-box](https://sing-box.sagernet.org/configuration/route/rule/); её фактическое действие, взаимодействие с DNS и правилами сайтов нужно проверить на VM. Сейчас сайты и программы — отдельные черновики, не общий исполняемый план системной сессии. В пользовательский SOCKS-конфиг они не применяются.
