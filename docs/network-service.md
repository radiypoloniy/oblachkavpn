# Сетевая служба

Служба `OblachkaNetwork` работает от SYSTEM и делает то, на что у окна нет прав: поднимает TUN, меняет маршруты и DNS, ставит фильтры WFP. Ставит её установщик. Без службы (например, в сборке `out\app`) окно запускает помощника с запросом UAC, а внутри та же сетевая сессия.

## Поведение

- В режиме «Весь компьютер» прав администратора при каждом подключении не спрашивают.
- **Аварийное завершение окна не снимает защиту.** Служба оставляет сессию: туннель без ядра окна ничего не несёт, фильтры держат сеть закрытой, утечки мимо VPN нет. Снимают её «Восстановить сеть», новое подключение, остановка службы или перезагрузка.
- Штатный выход из приложения («Завершить» в трее, крестик при выключенном «сворачивать в трей») сначала снимает «Весь компьютер», потом закрывает окно.
- **Выход из сеанса Windows — не авария.** Служба получает от Windows уведомление о выходе (`SESSIONCHANGE`, `WTS_SESSION_LOGOFF`) и, если это сеанс окна-владельца, снимает сессию и гасит zapret. Это важно для «Завершения работы» с быстрым запуском: Windows не выключается, а усыпляет ядро вместе со службой, служба не перезапускается и при включении сама сессию не сняла бы — туннель без ядра и фильтры держали бы интернет закрытым до нажатия тумблера (так было до 0.14.3).
- Второй путь к тому же — пробуждение (`POWEREVENT`): если процесса окна-владельца больше нет, сессия снимается, как после перезагрузки. Если окно живо (обычный сон), ничего не меняется.
- Если канал окна со службой оборвался не по воле человека (система надолго замирала, служба перезапустилась), окно не остаётся в «Не подключено» при закрытой сети: оно снимает брошенную сессию и подключается заново, до трёх раз за 10 минут.
- Окно запоминает, был ли VPN включён, и при следующем запуске подключается само («Настройки → Подключаться при запуске»). Выключение тумблером отметку снимает, выход и выключение компьютера — нет.
- **zapret под защитой.** Пока `winws` работает, служба добавляет в подслой защиты разрешения для пакетов, которые WinDivert отправляет заново от имени System, — только на порты стратегии ([zapret.md](zapret.md#режим-весь-компьютер)).

## DNS прямых сайтов

Под «Весь компьютер» DNS разделён по пути трафика. Сайты, которые идут мимо VPN (российские, zapret, правила «напрямую»), разрешает DNS физической сети, остальные — DoH через туннель. Окно передаёт список доменов командой `DirectDns` частями, служба проверяет каждое имя и пишет `direct-dns.json` в свою папку (писать туда может только она). Ядро туннеля читает этот файл как набор правил DNS и перечитывает при изменении, так что переподключаться не нужно. Прямой выход ядра туннеля тоже разрешает имена через DNS сети. Подтверждено захватом трафика на стенде: запросы к прямым сайтам уходят в DNS сети, остальные наружу не выходят.

## Проверка связи

Окно проверяет связь каждые 45 секунд двумя путями:

1. **Через SOCKS ядра** — жив ли сервер. Две-три неудачи подряд запускают поиск рабочего сервера.
2. **Как обычная программа** (только «Весь компьютер», `SystemPathProbe`) — запрос без прокси, по маршрутам Windows: через туннель, защиту и, при «Российских сайтах напрямую», мимо VPN. Ядро может отвечать по SOCKS, а трафик компьютера при этом не проходить — так было в 0.13.1, и окно показывало «Защищено» при мёртвом интернете.

Если второй путь не работает две проверки подряд, окно один раз пересобирает «Весь компьютер». Если не помогло — главный экран показывает «Интернет закрыт» (или «Сайты напрямую не открываются») с кнопкой «Выключить VPN и открыть интернет», и приходит уведомление в трее. Проверка продолжается: если путь оживёт сам, карточка уйдёт.

## Если интернет пропал

От быстрого к крайнему:

1. «Остановить» в окне или «Выключить VPN и открыть интернет» на карточке — защита и туннель снимаются сразу.
2. Выход из Облачки через трей.
3. «Настройки → Для продвинутых → Восстановить сеть» — если окно упало, а защита осталась.
4. Перезагрузка, выход из Windows или выключение компьютера: служба снимает оставленную сессию. «Полный сброс сети Windows» для этого не нужен.

## Граница доверия

Служба работает от SYSTEM, поэтому:

- **Ставится только из Program Files.** `Oblachka.exe --install-service` отказывает (код 3), если exe лежит в папке, куда пишет пользователь. Иначе любая его программа подменила бы `Oblachka.exe` и получила SYSTEM.
- **Подчиняется только своей копии.** По PID клиента канала служба определяет путь его exe. Допустимы только `Oblachka.exe` и `Oblachka.Tests.exe` из папки самой службы, а писать туда может только администратор.
- **Окно проверяет службу.** PID сервера канала должен совпасть с PID службы по данным диспетчера служб, поэтому программа, занявшая имя канала раньше, не пройдёт.
- **Канал только для локальных пользователей.** ACL: SYSTEM — полный доступ, INTERACTIVE — чтение и запись, NETWORK — запрет.
- **Журнал в ProgramData с собственными правами.** SYSTEM и администраторы — полный доступ, пользователи — только чтение. Папку, созданную до службы кем-то без прав администратора, служба пересоздаёт, чтобы журнал нельзя было подложить.

Не закрыто: программа того же пользователя может управлять запущенным окном (отладка, внедрение кода), как у любого клиентского VPN. Подписи Authenticode пока нет.

## Протокол канала

Каждое сообщение — четырёхбайтная длина (little-endian) и JSON до 8192 байт. Обязательные поля: версия, `RequestId`, операция и аренда (`Lease`). Неизвестные и повторные поля отклоняются.

| команда | что делает |
|---|---|
| `Acquire` | применить сетевую сессию: адреса входа, режим, вход прямого трафика ядра |
| `Heartbeat` | продлить аренду (клиент шлёт каждые 3 с; без сообщений 15 с — откат) |
| `Release` | снять свою сессию и вернуть сеть |
| `Recover` | снять сессию, оставленную прежним владельцем |
| `Repair` | исправление из «Сети Windows» (сброс прокси, DNS и т. п.) |

В аренде нет ключей, подписок, путей запуска или команд оболочки, только ограниченный сетевой запрос. Ответы не содержат текста внутренних исключений.

## Команды

| команда | что делает | коды выхода |
|---|---|---|
| `Oblachka.exe --install-service` | регистрирует службу для этой копии, автозапуск, перезапуск при сбое | 0; 2 нет прав; 3 не Program Files; 4 отказ SCM |
| `Oblachka.exe --uninstall-service` | останавливает (сеть возвращается) и удаляет | 0; 2; 4 |
| `Oblachka.exe --network-service` | точка входа для диспетчера служб | — |
