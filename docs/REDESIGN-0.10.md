## 14 октября, вечер: отклик, перенос подписок, гонка остановки

- **Отклик серверов при запуске** (`ServerPing`): время TCP-рукопожатия с каждым узлом, восемь параллельно, без ядра. Запускается при старте, после загрузки подписки, при открытии «Всех серверов» и раз в 10 минут. Под «Весь компьютер» не обновляется: защита пропускает к узлам только ядро, а запрет на этом компьютере не считается «нет ответа». Свежий полный замер «Проверить все» важнее отклика; автовыбор и сортировка учитывают оба. Hysteria2 (UDP) пропускается.
- **Перенос из других клиентов** (`ForeignClients`, `WinSqlite`): экран ключа показывает подписки из Happ (журнал обновлений — база зашифрована), Throne, Hiddify, v2rayN (SQLite через системный winsqlite3.dll), NekoBox, v2RayTun, FlClash(X), Clash Verge. Нажатие загружает подписку и подключает. Ключ на экран не выводится — только хост и четыре последних знака. Только HTTPS-адреса; отдельные профили без подписки не переносятся.
- **Исправлено: «Выключить» во время запуска «Весь компьютер» оставлял сеть закрытой**, а окно показывало «Не подключено». Отмена посреди Acquire закрывала канал, служба считала окно погибшим. Теперь Acquire доводится до конца, затем обычный Release. «Защищено» — только после подтверждения туннеля службой.

Проверено: самопроверки 192, UI 36; на VM через установщик 5b9d62b — перенос из Happ → «Защищено», остановка через 0,3 / 0,8 / 1,5 с после включения и после «Подключить лучший» — ядро снято, фильтров 0, интернет есть. Отклики на VM проверить нельзя, пока на хосте включён «Весь компьютер» Облачков: VirtualBox на хосте тоже не пускают к узлам сервиса.

## Паритет: выбор программ и маршрутизация по спискам

**Выбор программ** (`InstalledApps`, `ShellLinks`, `AppPicker`). «Правила → Программы → Выбрать программы» открывает список программ компьютера: ярлыки «Пуск» (в том числе Discord и другие на Squirrel), установленные из реестра, запущенные окна. Имена без версий, без установщиков и своих файлов. Поиск по первым буквам любого слова, с транслитом («тел» → Telegram), не той раскладкой («еуд») и обратно («yand» → «Яндекс Музыка»). Несколько программ сразу, одно действие, «Выбрать файл…». В списке правил — имя и значок. Правило по-прежнему — имя файла, договор со службой не менялся. На этом компьютере: 46 программ за 1,3 с в фоне.

**Маршрутизация по спискам** (`RoutingProfile`, `GeoDat`, `GeoStore`, `RoutingCompiler`).
- Сервис присылает правила заголовком `routing: happ://routing/add/<base64>` (формат Happ, Remnawave). Клиент разбирает его и предлагает на главном экране включить, скачав базы адресов.
- Встроенный набор «Российские сайты напрямую»: .ru, .рф, .su, geosite:category-ru.
- Базы geosite.dat/geoip.dat разбираются своим кодом; категории разворачиваются в списки в конфигурации ядра.
- Исполняет ядро подключения (Xray/sing-box) по имени из SNI. В режиме «Весь компьютер» прямой трафик ядра возвращается в туннель, служба выпускает его по пути ядра (флаг `CoreDirect`). Списки в службу не передаются.

Проверено: самопроверки 196 (в том числе разбор, базы, конфигурации, проверенные настоящими Xray и sing-box), UI 37; на живой подписке — 852 домена и 229 точных имён напрямую, Госуслуги/Сбер/Ozon/VK/Яндекс напрямую, YouTube/ChatGPT через VPN, все три конфигурации приняты ядрами.

**Не проверено в живом туннеле.** На VM нельзя, пока на хосте включён «Весь компьютер» Облачков. Риск, который проверка должна закрыть: если служба не узнает процесс ядра, прямой трафик ядра вернётся ему же — петля. Проверить: включить «Российские сайты напрямую» в «Весь компьютер», открыть ya.ru и 2ip.ru (должен показать адрес провайдера, не VPN), youtube.com (адрес VPN).

## 15 октября: маршрутизация починена, «Автовыбор», ссылки, QR

**Маршрутизация в «Весь компьютер» не работала** (сообщил пользователь: российские сайты не открывались). Причины, найденные на VM по числу соединений:
1. служба теряла флаг прямого трафика ядра в двух местах (`SingBoxTunnelProcess`, `WindowsTunnelBackend.Apply`);
2. правило ядра туннеля по пути процесса не срабатывало даже с `find_process` — один запрос к ya.ru порождал 11 тыс. соединений ядра и 24 тыс. у sing-box, окно зависало.

Теперь ядро окна отдаёт «напрямую» на отдельный локальный вход SOCKS ядра туннеля (127.0.0.1, логин и пароль на сессию, передаются в аренде, в журнал не пишутся), и всё пришедшее туда уходит мимо туннеля первым правилом. На VM: ya.ru по IP — 302 за 0,5 с, ядро 28 соединений, вход без пароля отказывает. Правила программ «напрямую» в туннеле проверены тоже.

Попутно — падение окна при одновременной остановке ядра из подбора и сессии (`Engine.Stop`); теперь последняя внутренняя ошибка пишется в `%LOCALAPPDATA%\Oblachka\crash.txt` (тип и стек, без текста).

**«Автовыбор»** переключает при обрыве всегда (не только при «Переключать при обрыве»), по всем узлам подписок, от быстрого к медленному; обрыв подтверждается за ~45 с вместо 2–3 минут; выбор запоминается; включение начинается с лучшего. При неудачной проверке заголовок — «Связь пропала», а не «Защищено».

**Ссылки `oblachka://`** (add/import/install-config/key), регистрирует установщик; подписка добавляется после подтверждения. На VM: запуск по ссылке → «Защищено» за 3,6 с; при работающем окне ссылка приходит в него.

**QR-код**: свой декодер (без пакетов), «Сканировать QR-код на экране» и Ctrl+V с картинкой. 49 из 49 тестовых картинок segno (версии 1–40, повороты, повреждения, код в снимке экрана), настоящий экран — 139 мс.
