# Интеграция с Remnawave

Панель и рабочие серверы не изменялись. Клиент использует обычный GET пользовательской HTTPS-подписки с `User-Agent: RoutePilot/0.3`, а не административный API панели. Правило с префиксом `RoutePilot/` подходит и для 0.3. Теперь можно явно добавить до пяти полных резервных адресов; никакого переписывания токенов между доменами нет.

По [официальной документации шаблонов](https://docs.rw/learn-en/templates/) формат определяется по клиенту; Base64 служит запасным вариантом. Чтобы получать полный Xray outbound с XHTTP extra, для собственного клиента лучше явно настроить выдачу Xray JSON. Документация [Response Rules](https://docs.rw/learn-en/routing-rules/) позволяет сопоставить User-Agent с типом ответа и шаблоном.

В `routepilot-response-rule.example.json` сохранён пример **одного правила**, которое можно добавить в соответствующий список правил панели после проверки её версии. Оно не является конфигурацией всей панели и не должно заменять существующие правила. Порядок имеет значение: верхнее совпавшее правило определяет ответ. Здесь нет токенов, узлов и пользовательских данных.

На реальном тестовом пользователе проверить:

1. Конечный URL возвращает JSON/текст, а не HTML или redirect.
2. В JSON используются VLESS `settings.vnext` и транспорты, поддерживаемые Xray 26.9.9.
3. Сохранились XHTTP path/mode/extra/downstream, REALITY SNI/pbk/sid и flow.
4. Набор узлов и сроки доступа соответствуют тестовому пользователю.
5. Поведение ответа при истёкшей/отозванной подписке понятно клиенту.

Прототип пока не обрабатывает метаданные трафика/срока действия в заголовках, объявления панели, remote routing и HWID-регистрацию. Если панель требует HWID, эту возможность надо реализовать отдельно; не ослаблять правила для существующих пользователей ради прототипа. Возможный подход для будущей регистрации устройства — случайный идентификатор установки с явной регистрацией, без чтения аппаратных серийных номеров.

В текущую сборку импортируются только outbounds. Если шаблон зависит от DNS, routing, дополнительных outbounds или внешних файлов, его нельзя считать полностью поддержанным. Нужен отдельный клиентский шаблон для возможностей RoutePilot или следующий этап нормализации профилей.
