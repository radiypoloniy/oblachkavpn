# Сравнение с Throne на отдельном стенде

План испытаний, не результат. Выполнять на Windows VM со снимком, после базовой проверки TUN. Профили пользователь предоставляет явно; установленные клиенты и личные хранилища автоматически не читать.

## Фиксируем условия

- Версия Windows, VM, ресурсы, тип сети/NAT, версии клиентов и ядер, режим SOCKS/TUN, MTU, DNS/IPv6-политика.
- Один тестовый сервер и эквивалентные TLS/SNI/REALITY/transport параметры. Разные ядра фиксировать как отдельную переменную, а не приписывать эффект интерфейсу.
- Чередовать порядок клиентов, не запускать два TUN одновременно. Снимок восстанавливать перед каждым аварийным сценарием.
- Контролируемые HTTPS-цели и download/upload endpoint с известными лимитами; общий бюджет трафика объявить до прогона. Никаких автоматических больших speedtest по всем серверам.
- Обезличенный отчёт не содержит адресов, имён узлов, ссылок подписки, UUID, ключей или истории браузера. Сырые захваты трафика отдельно на стенде, не прикладывать автоматически.

## Сценарии и метрики

| Сценарий | Что измеряем | Признак отказа |
| --- | --- | --- |
| 20 холодных подключений на транспорт | Время до первого успешного HTTPS, доля успеха, медиана и p95 | Статус Running без работающей передачи |
| Работа 60 минут | Успешные/неудачные запросы, CPU/RAM с шагом 5 с, число переключений | Растущая память, ложное восстановление |
| Передача и параллельные запросы | Контрольная сумма, длительность, доля отказов | Повреждение/зависание, потерянный процесс после отмены |
| Одна цель проверки недоступна | Число восстановлений при исправной второй цели | Исправный туннель выключается |
| Задержка близких кандидатов колеблется | Число смен узла и разрывов текущей передачи | Частые смены без заметного выигрыша |
| Выключена виртуальная сетевая карта | Повторы в минуту, поведение после возврата сети | Бесконечные повторы/выход за бюджет |
| Сон/пробуждение, смена uplink | Время восстановления, корректность входных исключений | Зацикливание маршрута, неверный DNS |
| Падает core/UI/helper по отдельности | Удаление собственных ресурсов, диагностика незавершённого восстановления | Сеть остаётся повреждённой, удаляются чужие настройки |
| Подписка: offline/401/403/пусто/новые ключи | Сохранённые узлы и выбор, частота повторов | Удаление рабочего списка, обход отказа авторизации зеркалом |
| Защита при обрыве | Контролируемый исходящий TCP/UDP/IPv6 и DNS при каждой фазе аварии | Запрещённый пакет уходит вне туннеля |

Сейчас наш пользовательский режим — SOCKS5/TCP. Для него нельзя выставлять результат «TUN/UDP/kill switch прошёл». Проверки DNS/IPv6 и защиты от обхода требуют наблюдения сетевого трафика на стенде: зелёная строка приложения этого не доказывает.

## Форма результата

Для каждого сценария: обезличенный ID прогона, версия клиента/core, режим, число попыток, успехи/отказы, медиана/p95, CPU/RAM, число смен узла, длительность потери передачи, восстановление сети, комментарий о различиях условий. При 20 попытках p95 предварительный; публиковать размер выборки и сырые обезличенные времена. Единичный быстрый замер не считается преимуществом.

Первый допуск: базовая передача, корректная остановка и подтверждённое восстановление собственных изменений. Следующий: повторяемые аварийные тесты. Расширение аудитории — после прохождения этих этапов, без обещаний уже доказанной устойчивости.
