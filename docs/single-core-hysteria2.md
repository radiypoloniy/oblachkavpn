# Hysteria2 в одном ядре — 2 ноября 2026

База: ff0687e. В установленном клиенте обнаружены отдельные sing-box.exe окна
и oblachka-core.exe службы. Сводка сохранённых настроек, прочитанная только в
памяти, показала выбранный Hysteria2 с обычным TLS/SNI/ALPN. Ключи, адреса,
названия профилей и исходный JSON не выводились и не сохранялись на диск.
Настройки и работающее подключение не менялись.

Причина второго процесса: DirectOutbound и политика службы допускали VLESS,
Trojan, Shadowsocks, AmneziaWG и встроенный Xray, но не Hysteria2. Само ядро
туннеля уже собрано с поддержкой QUIC/Hysteria2. Профиль оставался на прежнем
пути TUN → локальный SOCKS → отдельный sing-box → сервер.

## Изменение

Обычный Hysteria2 теперь проходит через существующий путь одного ядра:
TUN → выход Hysteria2 в oblachka-core → сервер. Engine.Carried не запускает
второй процесс. Переключатель серверов, проверка связи через его именованный
выход и прежний local-core для неподдерживаемых профилей сохраняются.

Поддержаны пароль, TLS с проверкой сертификата, исходные SNI/ALPN, up_mbps,
down_mbps, salamander и ограничение network=tcp/udp. Отсутствующие параметры
скорости не подменяются: выбор BBR/Brutal остаётся прежним. Служба заново
собирает выход из проверенных полей; адрес — только IP из текущей аренды.

Специальные TLS-пины/сертификаты, port hopping и остальные неподдерживаемые
поля не удаляются ради экономии: такой профиль остаётся на прежнем пути.
Фрагментация и запрет прямого выхода в текущей сессии по-прежнему запрещают
режим одного ядра. Ограничения размера аренды и числа выходов не расширены.

Поддержка полей сверена с исходниками закреплённого sing-box 1.14.4 и
[официальным описанием Hysteria2](https://sing-box.sagernet.org/configuration/outbound/hysteria2/).

## Измеренная память двух сетевых процессов

Три пары отдельных запусков настоящих бинарников. В каждой паре один вариант
передаёт трафик через собственное ядро и отдельный официальный sing-box,
другой — через собственное ядро с Hysteria2. Сервер Hysteria2 один и тот же,
локальный; его память в суммы не включена. В каждом варианте 100 открытых
TCP-соединений через настоящий зашифрованный Hysteria2; проверено 409600 байт echo.
После прогрева пять образцов памяти. Ни ОС, ни стенд не принуждают GC/working-set
trim; штатное освобождение памяти при старте ядра остаётся его обычным поведением.

Сертификат генерируется на запуск. Он доверен только конфигурациями процессов
стенда; проверка сертификата включена, хранилища сертификатов Windows не меняются.
Трафик только loopback; TUN и системные маршруты в этом стенде не создаются.

| Пара | Private Bytes двух → одного, МиБ | Private Working Set двух → одного, МиБ |
| --- | ---: | ---: |
| 1 | 124,35 → 63,10 | 30,09 → 15,99 |
| 2 | 127,13 → 63,30 | 32,34 → 16,61 |
| 3 | 126,88 → 63,52 | 31,69 → 16,54 |
| Медианы | **126,875 → 63,305** | **31,688 → 16,543** |

Экономия медиан: **63,57 МиБ private bytes и 15,14 МиБ private working set**
сетевых процессов. Рабочие наборы с общими страницами не складываются как
физическая экономия. Размер самого Oblachka.exe этим изменением не уменьшается;
экономия относится к сумме ядер и действует при открытом окне и в трее.
В живом TUN результат зависит от трафика, настроек и поведения Go/Windows.
Нельзя обещать те же числа на другом устройстве или по одному процессу GUI.
CPU и пропускная способность этим сравнением не оценивались.

## Безопасность, проверки и совместимость

- Строгий список полей, точный IP из аренды и порт 1–65535. Не принимаются
  detour, bind_interface, внешние файлы, insecure, TLS без проверки, неизвестные
  настройки, неверные типы скорости/ALPN, отрицательные скорости и чужие IP.
- Go-тесты проводят настоящий TCP и UDP через Hysteria2 с salamander и без него.
  Неверное имя сертификата и неверный пароль не дают успешного соединения.
  Тестовые центры доверия не добавляются в Windows.
- Проверены сборка полной TUN-конфигурации настоящим ядром, сохранение параметров
  профиля, прежний путь для TLS-пинов/port hopping и сохранение блокировки при
  отказе переключения на fallback. Остальные защитные тесты также проходят.
- build.ps1: 0 предупреждений. test.ps1: 437 логических, 74 оконные и 20 фоновых
  проверок; Go: 12 тестов, включая новые сценарии Hysteria2. Все успешно.
- Бинарник и зависимости Go не менялись: Hysteria2 уже находится внутри ядра.
  SHA256 остаётся B0285ED543D041578A78D489A4C83E6CEA37B335CB20D36EF40F591D99908ED3.

Политика проверяется и клиентом, и привилегированной службой. Для применения
нужен полный установщик с обновлением службы, затем новая VPN-сессия. Старую
службу не заставляем принимать новые типы выходов и её проверки не обходим.
В пробе rc.9 вместе с этим находятся изменения CPU-планировщика и интерфейса
из предыдущих этапов. Пользовательская проверка реального TUN после установки
остаётся необходимой; установленная сессия в ходе разработки не заменялась.

## Воспроизведение

```powershell
dotnet build scripts/MemoryProbe/MemoryProbe.csproj -c Release -o out/hysteria-probe --configfile src/NuGet.Config
out/hysteria-probe/MemoryProbe.exe --hysteria-cores out/app/tools/oblachka-core.exe out/app/tools/sing-box.exe out/hysteria-memory.json
```

Сырые локальные отчёты: out/cpu-stage3/hysteria-core-memory.json,
hysteria-memory-summary.json и hysteria-medians.json. Отчёт не содержит
паролей или сертификатов. Диагностика пользовательских профилей и её временный
инструмент остаются в игнорируемой папке out, не входят в Git или установщик.
