# Локальный IPC helper

Сообщения передаются через локальный Windows named pipe. Имя создаётся случайно на каждый запуск; первая серверная инстанция эксклюзивна. Само имя не служит аутентификацией.

## Доверие

Сервер создаёт защищённый ACL с правами только для SID текущего пользователя и проверяет PID клиента через GetNamedPipeClientProcessId. Клиент проверяет владельца pipe и PID сервера через GetNamedPipeServerProcessId относительно конкретного запущенного процесса. Обе стороны удерживают handle процесса. При завершении владельца другой процесс с повторно выданным PID не получает сессию.

Использован явный User SID: .NET 8 CurrentUserOnly имеет известную проблему с Owner SID. [Исходное описание .NET](https://github.com/dotnet/runtime/issues/123903), [API создания pipe с ACL](https://learn.microsoft.com/en-us/dotnet/api/system.io.pipes.namedpipeserverstreamacl.create).

Текущая схема подходит для приложения и helper под одной учётной записью. Служба SYSTEM и повышение прав через другую учётную запись потребуют отдельной проверки токенов и ACL. Проверка PID не заменяет подпись бинарника и защищённую установку будущего привилегированного helper.

## Протокол и срок жизни

Каждое сообщение имеет четырёхбайтную длину little-endian и JSON до 8192 байт. Версия, RequestId, операция и Lease обязательны; неизвестные/повторные поля и команды отклоняются. Команды: Acquire, Release, Heartbeat. Lease содержит только ограниченный сетевой запрос; никаких ключей, подписок, путей запуска или команд оболочки.

Сервер обслуживает один процесс-владелец и одну активную lease. Release чужого LeaseId не затрагивает ресурсы. Очередь последних 64 RequestId отклоняет недавние повторы; это защита от случайного дублирования, не криптографический протокол защиты от replay. Клиент проверяет соответствие RequestId ответа запросу. При ошибке или таймауте pipe закрывается: запоздавший ответ не попадёт в следующий запрос.

Ожидание подключения ограничено 15 секундами; интервал без сообщения — 15 секунд. При потере связи, истечении интервала, отмене или завершении владельца вызывается восстановление сетевой сессии. При конфликте журнал сохраняет RecoveryRequired. В ответах нет текста внутренних исключений. Heartbeat должен присылаться клиентом чаще этого лимита; автоматический клиентский координатор добавляется следующим изменением.

## Проверка

Проверяются настоящие named pipes, корректный обмен, чужой LeaseId, таймаут, неверный PID клиента/сервера и запуск отдельного дочернего helper-fixture. Backend остаётся синтетическим в памяти; единственная запись — изолированный журнал теста. Опции --helper-fixture/--helper-idle-fixture предназначены только для тестов и не изменяют сеть Windows.
