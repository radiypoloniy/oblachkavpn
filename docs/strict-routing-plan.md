# Строгие маршруты при выключенном основном VPN

В 0.23.0 привязки работают внутри действующей сессии «Весь компьютер».

## Реализация

- Для привязок только по точному пути к .exe основной выход переключается внутри аренды. Обычный трафик идёт через прямой выход ядра, а явное «Через VPN» блокируется до возобновления. При включённом «Без VPN — без интернета» во время паузы блокируется весь обычный трафик. Закреплённые выходы сохраняются в обоих случаях.
- Привязки остаются глобальными. Они имеют приоритет над обычными правилами, импортом и списками. Редактор показывает пересечения до сохранения. Набор, исключающий закреплённый сервер, требует сначала изменить привязку или список серверов. В действующей сессии сохранённое изменение отмечается отдельно до применения.
- Для точных путей ядро блокирует соединения, у которых не смогло определить процесс. Дочерний процесс с другим .exe требует отдельного правила. DNS следует закреплённому выходу при совпадении по имени или известному пути процесса. Обычные запросы при выключенном основном выходе используют прямой DoH. Для запросов через общий системный резолвер Windows принадлежность запросившему приложению ещё нужно подтвердить.
- При активных привязках отключены физические разрешения для программ «напрямую», исключения подсетей и прямые входы, которые теряют сведения об исходном процессе. Постоянный подслой WFP остаётся при снятии аренды, в том числе после остановки службы или выхода из Windows. До восстановления туннеля он закрывает внешний выход приложений. После загрузки Windows постоянные фильтры загружает BFE. Снять строгую блокировку можно через «Восстановить сеть» с подтверждением.
- Для доменных привязок в общем браузере отдельная пауза пока недоступна. Для неё нужна проверка поведения с ECH, DoH и переиспользованием соединений. Окно до запуска BFE и сценарии с действующими TCP/QUIC-соединениями требуют приёмки с захватом на физическом адаптере.

## Поведение

- Отделить основной выход от состояния туннеля и строгой защиты. Выключение или пауза основного VPN переводит обычный трафик на прямой выход ядра; активные строгие маршруты остаются в туннеле. Полное отключение защиты требует отдельного подтверждения.
- Недоступность закреплённого выхода блокирует только его цели. При отказе всего туннеля доменная гарантия требует удерживать блокировку выхода до восстановления. Определить отдельно поведение после выхода из Windows, перезапуска службы, загрузки системы и при включённом «Без VPN — без интернета».
- Явно определить смысл обычного «Через VPN» при отключённом основном выходе. Согласовать область строгих привязок с наборами и миграцией: сейчас привязки глобальны, а набор может исключить закреплённый сервер.

## Порядок работ

1. Добавить переключение основного выхода внутри текущей аренды. Развести ручную остановку основного VPN, паузу, восстановление строгой защиты и фактическое состояние фильтров. Разделить DNS строгих и обычных маршрутов.
2. Устранить обходы: обычное правило, импорт и смена набора не должны перекрывать строгую привязку; явно разрешать конфликты перед сохранением. Физический обход WFP для браузера, локальные исключения и прямой вход ядра тоже подлежат проверке. Сначала перекрыть обход, затем применить правила и прервать старые соединения. Отдельно показывать сохранённое и применённое состояние.
3. Определить поддерживаемую область гарантии. Начать с точного пути к программе и проверить дочерние процессы. Для доменов проверить ECH, DoH, кэш, общие IP, повторное использование HTTP/2 и HTTP/3. Не разрешать нераспознанный трафик напрямую в области, для которой обещана строгая защита.
4. Спроектировать независимую блокировку на основе WFP. Проверить окна между снятием и установкой фильтров, аварийный и штатный перезапуск службы и порядок защиты при загрузке Windows. Предусмотреть явное локальное восстановление сети.

## Приёмка на Windows

Основной VPN включён → выключить или поставить на паузу → обычный сайт идёт напрямую, Claude остаётся на Сербии → оборвать Сербию → только Claude заблокирован → оборвать TUN или службу → физического выхода защищённого трафика нет. Повторить с открытыми TCP и QUIC-соединениями, IPv4 и IPv6, правилом «Браузер напрямую», сменой набора, сном и перезагрузкой. Проверять адреса выхода и захват пакетов и DNS на физическом адаптере. Имеющийся loopback-тест нескольких выходов дополняет этот стенд.
