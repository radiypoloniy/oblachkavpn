# Опыт клиентов и решения для Облачки

Дата проверки: 11 октября 2026. Изучены официальные документация и репозитории Happ, Throne, Hiddify, v2rayN и Amnezia. Это анализ заявленных механизмов, не сравнительный прогон приложений. Данных о долях использования в РФ не собирали; слова «популярный» и число функций не доказывают качество соединения. Исходники конкурентов в проект не копировались.

## Что полезно перенять

| Клиент | Подтверждённый механизм | Решение для нас |
| --- | --- | --- |
| Throne | URL-тест через профиль, история задержки/jitter, готовые резервы, порог переключения; проверки не останавливают текущий профиль | Улучшать выбор по серии результатов, избегать лишних переключений, затем разрешить ограниченные фоновые измерения |
| Happ | Миграция URL/домена подписки, выбор способов проверки доступности, предварительное разрешение адреса сервера | Отдельно проектировать восстановление подписки и bootstrap DNS; сохранять SNI при подключении по IP |
| Hiddify | Автовыбор по задержке, обновление подписок, сведения о сроке/трафике, региональные настройки | Простой основной сценарий с подробностями в диагностике; региональные правила должны иметь версию и объяснимое действие |
| v2rayN | Разные ядра, форматы подписок, явные правила proxy/direct/block | Проверять возможности конкретного ядра до запуска; один нормализованный план правил, отдельные компиляторы |
| Amnezia | Правила для сайтов и программ, разные транспорты, собственные серверы | Маршруты сайтов/программ объяснять одинаково; альтернативный транспорт предлагать только при наличии совместимого узла |

Источники: [Throne: тесты и выбор](https://throneproj.github.io/guides/testing/), [Happ: параметры](https://docs.happ-proxy.com/ru/getting-started/premium-functionality.md), [Hiddify](https://github.com/hiddify/hiddify-app), [ядра v2rayN](https://github.com/2dust/v2rayN), [подписки v2rayN](https://github.com/2dust/v2rayN/wiki/Description-of-subscription), [правила v2rayN](https://github.com/2dust/v2rayN/wiki/Description-of-custom-routing-rules), [Amnezia](https://github.com/amnezia-vpn/amnezia-client).

Throne также описывает группы подписок, сохранение измерений неизменённых профилей и получение квоты из Subscription-UserInfo. Нам нужны устойчивые идентификаторы узлов от сервиса: выбор по уникальному имени при смене ключа остаётся временным решением. [Источник](https://throneproj.github.io/guides/subscriptions/).

## Существенные границы

Документация Throne отдельно описывает фильтры DNS/IPv6 в Strict Route и прямо говорит, что TUN не является kill switch. Наличие Strict Route не доказывает блокировку всего трафика при аварии. В нашей реализации защита при обрыве — самостоятельная политика Windows backend с проверкой на VM. [DNS-защита](https://throneproj.github.io/advanced/windows_tun_mode/), [TUN и права](https://throneproj.github.io/guides/tun_mode/).

Happ описывает HWID-привязку и управление настройками через мобильные push-службы. Это не основание переносить такой канал управления в Windows. Если понадобится лимит устройств, предлагаем случайный идентификатор установки и отзыв регистрации на сервере; не сбор аппаратных серийников. Локальная проверка HWID сама по себе не обеспечивает серверное ограничение аккаунта. [HWID](https://docs.happ-proxy.com/getting-started/hwid-links.md), [push-controls](https://docs.happ-proxy.com/ru/getting-started/remote-push/controls.md).

## План следующей реализации

Это наши проектные решения, а не утверждения о внутреннем устройстве конкурентов.

1. **Политика качества без TUN.** Отдельные небольшие классы: история результатов, ранжирование, решение о переключении. Ограниченная история по отпечатку профиля; при изменении credentials/transport замеры сбрасываются. Ручной выбор имеет приоритет, один короткий успешный замер не вытесняет стабильно работающий узел. Сначала внедрить порядок кандидатов при подключении/восстановлении; переключение исправной сессии по скорости отложить.
2. **Подписка как независимый канал.** Использовать уже существующий SOCKS-путь загрузчика без разрыва подключения. При защите от обхода нельзя молча уходить на прямую загрузку. Кэш валидированного ответа, ETag с привязкой к endpoint, ограничение тела, 304 только с существующим кэшем. Миграция полного URL — через проверенную политику сервиса; не пересылать токен на произвольный домен из заголовка и не переносить секретный путь слепой заменой hostname.
3. **Контракт сервиса поверх Remnawave.** Версия схемы, стабильный node_id, исходное имя, необязательный country_code, список реально доступных транспортов, endpoints подписки и время действия. Подписанная конфигурация с защитой от старых версий; персональные данные только в шифрованном хранилище. Remnawave сохраняется. Название «Рабочий сервер», «Авто», «Обход» не заменять страной. Флаг — отдельные метаданные; отсутствие страны не повод угадывать геолокацию.
4. **После VM: единый Windows backend.** UI без admin, минимальный helper, журнал собственных изменений, проверка входных исключений до маршрутизации, явная DNS/IPv6-политика. Объединить правила сайтов/программ и определить поведение при смене сети. Защита при обрыве не должна препятствовать согласованным DNS/bootstrap/control запросам и восстановлению; исключения узкие и проверяемые.
5. **Закрытый сравнительный прогон.** Одинаковые профиль/сеть/сервер, закреплённые версии ядер, повторные прогоны Throne и Облачки. Сначала TCP/REALITY и XHTTP, затем UDP и транспортные эксперименты. Новый протокол обсуждать после выявления воспроизводимого ограничения стандартных вариантов.

Каждый блок — отдельный коммит с собственной проверкой. Региональные DIRECT-пресеты и любые изменения сети не включать как побочный эффект исследования. Прозрачная смена узла не гарантирует сохранение старых TCP-сессий: разрыв загрузки/звонка учитывать в измерении качества.

## Как измеряем «лучше»

Порядок теста и форма результатов — [CLIENT-BENCHMARK.md](CLIENT-BENCHMARK.md). Цели: меньше ложных восстановлений, меньше лишних переключений, предсказуемый выход после аварии, сохранённая подписка и быстрый первый успешный запрос. Сравнительный результат пока отсутствует. Обещание превосходства по стабильности или скорости до этих испытаний не подтверждено.
