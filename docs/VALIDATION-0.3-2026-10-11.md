## Новые сценарии

Резервный адрес после отказа основного, приоритет последнего успешного адреса, валидация списка полных HTTPS-ссылок, остановка по отказу доступа/отмене. Получение подписок проверяется подставным HTTP handler и контролируемым fetch delegate, без реального обращения к доменам пользователя.

Подбор: переход от неуспешного профиля к успешному, ограничение числа попыток, прекращение по HTTP-ошибке сайта, отмена и остановка драйвера. В реальном локальном стенде TCP/TLS и XHTTP/TLS дополнительно проверены переход от отклонённой Xray-конфигурации к рабочему туннелю, стабильный SOCKS-порт и правильная классификация HTTP 503 сайта проверки. Передача трёх параллельных блоков по 256 КиБ сохраняет точное содержимое.

WPF: импорт, два цикла запуска/остановки, успешное обновление без изменения активного процесса, сохранение списка и отложенного обновления после неудачи, применение отложенного списка с сохранением выбранного профиля после остановки, отмена обновления с завершением активного Xray по кнопке Stop.

Занятый SOCKS-порт вызывает явный отказ без перехода на другой порт. Сохранение порта действует только до выхода из приложения. Установленные TCP-соединения при смене профиля не сохраняются.

## Пределы

Автоматического фонового мониторинга/переключения, TUN, второго ядра, Hysteria2 и специализированного режима L0/L1 в этой версии нет. Реальные подписки, узлы и российские операторы в автоматических проверках не использовались. Контракт резервных источников проверен синтетически; реальные DNS/TLS/CDN потребуют отдельного стенда.

Сборка 0.2 в `app` не перезаписывалась. Личные данные и боевые серверные конфигурации не читались; сетевые настройки системы не изменялись. Файлы и тестовые каталоги не удалялись.
