# Поставка 0.8

## Локальная установка и обновление

Установщик — PowerShell-скрипт, не MSI/Setup.exe. Нужен .NET 8 Desktop Runtime x64. Он проверяет ZIP до записи файлов, создаёт отдельную папку `release-<version>-<guid>`, а затем атомарно обновляет `current.json`. Старые версии и резервные указатели остаются. Профили по-прежнему находятся в DPAPI-хранилище текущего пользователя, поэтому переезд папки не сбрасывает подписку.

```powershell
./install-package.ps1 -ArchivePath 'C:\path\Oblachka.zip' -InstallRoot 'C:\path\Oblachka-install' -ExpectedSha256 '<хеш из доверенного сообщения о выпуске>' -CreateShortcut
./launch-package.ps1 -InstallRoot 'C:\path\Oblachka-install'
./rollback-package.ps1 -InstallRoot 'C:\path\Oblachka-install'
```

Перед запуском новой/старой версии закрой предыдущий клиент через «Завершить» в трее. Автоматическая проверка интернета и скачивание обновлений ещё не подключены. Установщик не запускает ядро, не ставит службу и не меняет сеть/реестр. Ярлык создаётся только по `-CreateShortcut`, в выбранной папке, и использует текущий указатель версии. Если execution policy запрещает скрипт, не меняй глобальную политику: для закрытого теста можно распаковать ZIP вручную.

## Подпись пакета

В ZIP есть манифест с SHA256 и размерами всех файлов. Установщик требует доверенный SHA256 всего архива или отдельно закреплённый публичный ключ. При заданном публичном ключе подпись обязательна; неверная подпись не заменяется проверкой хеша. ZIP не может сам выбирать себе доверенный ключ.

```powershell
./create-release-key.ps1 -Directory 'C:\offline\Oblachka-release-key'
./package.ps1 -SigningKeyPath 'C:\offline\Oblachka-release-key\private.json'
./install-package.ps1 -ArchivePath 'C:\path\Oblachka.zip' -InstallRoot 'C:\path\Oblachka-install' -TrustedPublicKey 'C:\trusted\public.json'
```

RSA 3072 / SHA256 / PKCS#1 v1.5. Подписываются точные байты `release-manifest.json`; до распаковки проверяется каждый файл. Закрытый ключ не включается в архив/репозиторий. Ключ, создаваемый проверками, временный тестовый; для сервиса нужен отдельный постоянный офлайн-ключ и независимая доставка публичного ключа. Это подпись пакета, **не Windows Authenticode**. Сертификат подписи exe/helper и SmartScreen требуют отдельного этапа.

При отказе до смены указателя прежняя версия остаётся активной. Частично распакованная папка сохраняется для разбора. Откат переключает указатель, ничего не удаляя. Launcher дополнительно проверяет хеши выбранной установленной версии. Изменения пользовательского хранилища не откатываются; формат 0.8 сохраняет совместимость v1 и добавляет необязательные поля.

## Граница helper

`HelperProcessLifetime` связывает запуск с конкретным PID, затем использует проверенный named pipe и управляет асинхронным освобождением. При таймауте восстановления процесс принудительно не убивается. Это готовая точка подключения будущего установленного helper/UAC launcher, проверенная на отдельном процессе с имитацией сети. Реальный Windows backend, повышение прав и служба в пользовательский запуск не подключены до VM-проверки.
