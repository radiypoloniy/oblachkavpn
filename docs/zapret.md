# zapret: YouTube и Discord без VPN

«Настройки → Правила → YouTube и Discord без VPN» включает обход блокировок [zapret](https://github.com/bol-van/zapret) с набором стратегий [Flowseal](https://github.com/Flowseal/zapret-discord-youtube). Сайты из списков набора (YouTube, Discord и около 80 других) идут не через VPN, а напрямую, и фильтр провайдера обходит `winws`.

## Как это работает

1. **Подготовка.** Сетевая служба Облачки берёт манифест `zapret/manifest.json`: встроенный в программу или более свежий из этого репозитория. Затем скачивает архив Flowseal с его страницы релизов на GitHub, сверяет SHA256 архива и каждого нужного файла и распаковывает только эти файлы в `C:\ProgramData\Oblachka\zapret\<версия>`. Писать туда могут только SYSTEM и администраторы.
2. **Подбор стратегии.** Сначала окно проверяет сайты без обхода. Если всё открывается, обход в этой сети не нужен: сайты просто идут напрямую. Иначе стратегии пробуются по очереди (general, ALT, ALT2 …) до первой, при которой открываются все проверочные сайты. Проверка учитывает типичное «замирание» соединения на ~16 КБ. Выбор запоминается для сети: по хешу адаптера и шлюза.
3. **Работа.** Служба держит один процесс `winws` от SYSTEM. Он останавливается при выключении, выходе из Облачки, остановке службы и удалении программы.
4. **Если не помогло.** Если рабочей стратегии нет, сайты из списка остаются в VPN: обход не должен ломать то, что работало. Частичного успеха нет: напрямую сайты идут, только если открываются все проверочные.

## Режим «Весь компьютер»

zapret работает в обоих режимах. В «Весь компьютер» сайты из его списков идут мимо VPN через вход прямого трафика ядра туннеля, а стратегия проверяется через ядро.

Чтобы это работало вместе с защитой от утечек, служба делает одну вещь, которую нужно понимать:

- `winws` перехватывает исходящий пакет и отправляет его заново. Windows проверяет такой пакет повторно (слой `ALE_AUTH_CONNECT`) как **новое соединение от System** (pid 4), а не от программы, которая его открыла. Подтверждено журналом событий WFP на стенде (5157, `reauth=0`).
- Защита пропускает мимо туннеля только ядро Облачки, поэтому без исключения такие пакеты режутся. Так было в 0.13.1: гибли все сайты «напрямую» и соединение ядра с сервером VPN на порту 443, то есть пропадал весь интернет.
- Пока `winws` работает под защитой, служба добавляет в её подслой разрешения **только для System и только на порты, которые перехватывает стратегия** — они берутся из её `--wf-tcp` и `--wf-udp` (`WfpReinjection`). Если обновление набора Flowseal добавит порт, разрешение расширится само, и соединение с VPN не оборвётся.
- Обычная программа через это разрешение не пройдёт: её собственное соединение мимо туннеля режется раньше, ещё до перехвата. Мимо туннеля могут выйти только соединения ядра Windows на эти порты — на время работы zapret.
- `winws` остановлен — разрешения снимаются. Их номера зарезервированы в диапазоне фильтров защиты, поэтому при сбое службы журнал сессии снимает и их.

Если служба не смогла запустить `winws`, подбор сразу останавливается с причиной. Раньше он мгновенно перебирал все стратегии и сообщал, что ничего не работает.

## Безопасность

`winws` и драйвер WinDivert работают с правами SYSTEM, поэтому:

- **Аргументы стратегий проверяются по белому списку** (`ZapretArgs`). Пропускаются только параметры обхода. Ни `--debug` (запись файлов), ни `--daemon`, ни прочих. Файловые аргументы допустимы только внутри папки набора, без `..` и абсолютных путей.
- **Файлы сверяются по SHA256** из манифеста при подготовке и перед каждым запуском. Если антивирус удалил или подменил файл, запуска не будет, а окно объяснит, что делать.
- **Адреса VPN-серверов** передаются в исключения `winws`: соединение с VPN обход не трогает. `winws` работает только на физической сетевой карте (`--wf-iface`) и туннели других VPN не перехватывает.
- **Чужой zapret или GoodbyeDPI.** Если он уже работает, наш не запускается: два обхода на одном трафике ломают друг друга. «Сеть Windows» отличает наш `winws` (из папки Облачки) от брошенного чужого.

## Обновления

Задача `.github/workflows/zapret-update.yml` раз в день проверяет новый релиз Flowseal:

- архив сверяется с `digest` GitHub, манифест строит тот же код, что проверяет его в клиенте: неизвестный параметр или файл не из набора — и обновление не публикуется;
- **сменились только стратегии и списки** — манифест коммитится в `main`, клиенты подхватывают его без выпуска новой версии Облачки;
- **сменились исполняемые файлы** (`winws.exe`, `WinDivert*`, `cygwin1.dll`) — открывается запрос на слияние со ссылками на VirusTotal. Пользователи получат их только после ручного одобрения.

Ручной запуск (Actions → «Обновление zapret» → `force`) пересобирает манифест, даже если версия не менялась.

## Антивирусы

WinDivert — подписанный драйвер перехвата пакетов. Некоторые антивирусы считают его «нежелательной программой». Если файлы набора удалены, добавьте `C:\ProgramData\Oblachka\zapret` в исключения антивируса и включите обход заново.
