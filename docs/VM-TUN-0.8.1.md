# Проверка TUN в приложении 0.8.1

В виртуалке закрой старую сборку. Распакуй новую в отдельную папку и открой RoutePilot.exe.
Подписка загружается из сохранённого состояния той же учётной записи Windows.
Выбери рабочий сервер, открой «Диагностика» и нажми «Проверить TUN в виртуалке».
Подтверди запрос Windows на права администратора своей текущей учётной записи.
Ссылку, IP и порт вводить не нужно.

Отдельное окно показывает этапы проверки. После успешного запуска можно открыть браузер
в виртуалке. Нажми «Остановить проверку», затем закрой это окно. Основной VPN компьютера
не выключай. Перед первым испытанием используй уже сделанный снимок VM.

Приложение автоматически разрешает адрес выбранного сервера до изменения маршрутов,
закрепляет IP в копии профиля и сохраняет SNI/Host. Исходный профиль не изменяется.
Профиль передаётся дочернему процессу через DPAPI CurrentUser; ключей в командной строке
или открытом JSON нет. Запрос имеет ограниченный размер, срок действия и привязку
к процессу приложения. На обычном компьютере кнопка отключена, дочерний процесс также
проверяет тип машины и права. Определение VM по BIOS — защита от случайного запуска,
а не граница безопасности против вредоносного локального процесса.

Дочернее окно владеет двумя ядрами через Windows Job Objects. Сначала проверяется
SOCKS, затем конфигурация TUN, создание адаптера, два HTTPS-запроса без системного
прокси и рост счётчиков адаптера. Закрытие окна, смерть родителя или ядра останавливает
испытание. Одновременно допускается только одно окно TUN. После остановки проверяется
отсутствие именно созданного адаптера; полное восстановление DNS/маршрутов требует VM-теста.

Это экспериментальный TCP-стенд. UDP, проверенный kill switch, проверка утечек DNS/IPv6
и производственный системный режим пока не заявляются. Успешный HTTPS и счётчики не заменяют
проверку таблицы маршрутов и аварийного восстановления. При оставшемся адаптере или нарушении
сети восстанови снимок VM. Реальный TUN на основном компьютере при разработке не запускается.

Сборка не подписана Authenticode; в UAC возможен «Неизвестный издатель».
Если ядро не создаст адаптер, окно покажет ошибку и остановит принадлежащие ему процессы.
Сырые журналы ядер и адреса профиля в интерфейс ошибок не выводятся.
