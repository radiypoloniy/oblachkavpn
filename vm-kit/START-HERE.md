Откройте «Диагностика» → «Проверить TUN в виртуалке». Ручные команды ниже нужны только для отдельного технического стенда. [Подробности](../docs/VM-TUN-0.8.1.md).

# Как поднять тестовую Windows без опыта с виртуалками

Это отдельный компьютер в окне. Его виртуальный диск — обычный файл; Windows основного компьютера переустанавливать не нужно.

## Нужно ли заходить в BIOS

Нажми Ctrl+Shift+Esc → «Производительность» → «ЦП» → найди «Виртуализация».

- **Включено**: BIOS не нужен.
- **Отключено**: включи аппаратную виртуализацию. На Intel пункт обычно называется Intel Virtualization Technology / VT-x / VMX, на AMD — SVM Mode / AMD-V. Поставь Enabled и сохрани настройки. Точное место зависит от платы.
- В Windows 11 попасть в UEFI можно через «Параметры → Система → Восстановление → Расширенные параметры запуска → Перезагрузить сейчас», затем «Поиск и устранение неисправностей → Дополнительные параметры → Параметры встроенного ПО UEFI».

Другие параметры BIOS, Secure Boot и защиту Windows ради этого не отключай. [Инструкция Microsoft и ссылки на производителей](https://support.microsoft.com/en-us/windows/experience/enable-virtualization-on-windows).

## Один путь: VirtualBox и Windows 11

1. Скачай **VirtualBox для Windows hosts** с [официальной страницы](https://www.virtualbox.org/wiki/Downloads). Для этого стенда Extension Pack не требуется. Установка сетевого компонента может кратко прервать связь основного ПК — устанавливай, когда нет важной загрузки/звонка.
2. Скачай **Windows 11 ISO x64** с [Microsoft](https://www.microsoft.com/software-download/windows11). Это образ установочного диска, не установщик для основного ПК.
3. Открой VirtualBox → **Создать / New**. Имя: `Oblachka-test`. Выбери скачанный ISO, тип Windows 11 (64-bit). Для понятной ручной установки отметь **Skip Unattended Installation / Пропустить автоматическую установку**, если этот пункт показан.
4. Мои параметры стенда: **2 процессора, 6 ГБ RAM, динамический диск 80 ГБ**. Это рекомендация, не жёсткое требование. Если на основном ПК только 8 ГБ RAM, выдели VM 4 ГБ и закрой тяжёлые приложения; при нехватке ресурсов стенд будет медленным. Оставь основному компьютеру достаточно RAM и ядер.
5. В настройках виртуальной машины для Windows 11 должны быть включены **UEFI, Secure Boot и виртуальный TPM 2.0**. При выбранном типе Windows 11 мастер может настроить их сам. Это параметры VM, не BIOS основного компьютера. Сеть оставь **NAT**, без перенаправления портов. [Мастер VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/create-vm.html), [настройки и снимки](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html), [NAT](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/networkingdetails.html).
6. Нажми **Запустить / Start** и установи Windows **внутри окна VM** на виртуальный диск. Следуй обычному мастеру Microsoft; активация и учётная запись зависят от выбранной редакции и лицензии.
7. Внутри VM установи обновления Windows и **.NET 10 Desktop Runtime x64** с [официальной страницы .NET](https://dotnet.microsoft.com/download/dotnet/10.0). Нужен именно Desktop Runtime. Версия важна: клиент собран под .NET 10 начиная с 0.9, на .NET 8 он не запустится. Если в VM уже стоит .NET 8 от прежних проверок, его можно оставить — рантаймы ставятся рядом.
8. Перенеси только ZIP приложения: например, временно подключи отдельную папку с этим ZIP через Guest Additions / Shared Folders, скопируй файл и затем отключи общую папку. Не подключай весь диск, профиль Windows или Downloads. Общий буфер обмена для стенда не нужен.
9. Распакуй ZIP **внутри VM**, проверь обычный запуск приложения. Пока не запускай `test-tun.ps1 -Run`.
10. Выключи Windows внутри VM. Выбери VM → **Снимки / Snapshots → Сделать снимок / Take**. Назови `До TUN`. Это точка возврата после сетевых экспериментов.

На этом подготовка закончена. Напиши, что VM готова, и начнём испытание по `README.md` по шагам. Создание VM само по себе не проверяет TUN, утечки DNS или восстановление маршрутов.

Если мастер не запускает VM, запиши точный текст ошибки. Не надо сразу отключать Hyper-V или защиту Windows: современные версии VirtualBox могут работать через гипервизор Windows, а конкретную причину нужно проверить. Если есть Windows Pro/Enterprise, альтернативой служит встроенный Hyper-V; в Home его полноценная роль недоступна. [Microsoft](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/install-hyper-v?pivots=windows).
