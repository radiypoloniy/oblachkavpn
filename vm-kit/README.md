# Комплект проверки на Windows VM

Это экспериментальный стенд TUN sing-box, а не готовый привилегированный helper. IPC и журнал пока проверены с подменным backend; связь этих частей с реальными маршрутами требует следующей проверки на VM. На рабочем компьютере TUN не запускать.

1. Создать Windows 10/11 x64 VM, установить **.NET 10 Desktop Runtime x64** ([официальная страница](https://dotnet.microsoft.com/download/dotnet/10.0)), сделать снимок. Клиент собран под .NET 10 начиная с 0.9: на .NET 8 он просто не запустится. Скопировать весь распакованный комплект. Открыть приложение и запустить обычный SOCKS-профиль собственного тестового сервера.
2. Записать показанный приложением порт SOCKS и точные IPv4/IPv6 входного узла. Для этого стенда используйте IP в адресе профиля с исходным TLS SNI. Домены без закрепления IP и отдельный XHTTP downstream пока не подходят. Не копировать сюда UUID, пароль или ссылку подписки.
3. Проверить конфигурацию без изменения сети:

```powershell
.\vm-kit\test-tun.ps1 -SocksPort 10808 -PeerAddresses @('192.0.2.1')
```

Адрес 192.0.2.1 — документационный пример: заменить IP своего тестового узла. Команда генерирует новую папку vm-lab-*, конфигурацию без ключей и запускает только sing-box check. Ничего не удаляет.

4. На VM, в PowerShell от администратора, запустить эксперимент:

```powershell
.\vm-kit\test-tun.ps1 -SocksPort 10808 -PeerAddresses @('IP_ТЕСТОВОГО_УЗЛА') -Run -AcknowledgeDisposableVm
```

Перед -Run скрипт требует подтверждение одноразовой VM, проверяет модель виртуальной машины, права администратора и хеш sing-box. Проверка модели — защита от случайного запуска, не граница безопасности. Поддержаны стандартные названия Hyper-V, VMware, VirtualBox, KVM/QEMU и Parallels; другие VM пока не запускать этим скриптом.

## Матрица

Проверять TCP IPv4/IPv6, DNS, длительную загрузку, параллельные соединения, выключение локального SOCKS, Ctrl+C, завершение sing-box, сон/пробуждение, смену uplink, перезапуск VM. Каждый аварийный сценарий начинать с восстановленного снимка. UDP/QUIC заблокированы первой конфигурацией — это ожидаемый предел, не поддержка игр.

Для браузера использовать обычное соединение без вручную заданного SOCKS. На контролируемом сервере проверить адрес TCP-подключения; DNS проверять независимым захватом трафика VM. Отсутствие DIRECT outbound само по себе не доказывает отсутствие утечек. strict_route не заявляется как проверенный kill switch.

После Ctrl+C скрипт проверяет только собственный интерфейс. StoppedInterfaceAbsent не является доказательством полного отката всех DNS/firewall/маршрутов. NeedsManualReview требует отката снимка. Никакого автоматического удаления чужих объектов или восстановления широкого снимка сети нет.

Если ядро требует драйвер, не скачивать случайную DLL. Зафиксировать отказ и использовать официальный источник с проверкой происхождения; поставка драйвера и установка helper ещё не завершены.

Сохранить run-status.json, версии ядра/ОС и результаты матрицы без профиля, ключей и подписки. Этот результат нужен, чтобы выбрать реальные API владения интерфейсом и маршрутов, реализовать Windows backend и включить системный режим в приложении.

Конфигурация подготовлена по официальным схемам [TUN](https://sing-box.sagernet.org/configuration/inbound/tun/), [SOCKS](https://sing-box.sagernet.org/configuration/outbound/socks/), [DNS HTTPS](https://sing-box.sagernet.org/configuration/dns/server/https/) и проверена бинарником sing-box 1.14.3. Пока выполнена проверка синтаксиса, не реальная передача через TUN.
